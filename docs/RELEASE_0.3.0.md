# Reader 0.3.0：Google Drive 多电脑同步

0.3.3 修复新笔记的延迟自动聚焦抢走标题输入焦点的问题，保留用户已选择的输入位置；本地重现旧行为后，对应回归与相关笔记场景共 21 项通过。

0.3.2 修复 Windows ARM／Git Bash 下安全凭据辅助进程在 `Add-Type` 阶段卡住的问题，改为直接加载系统 .NET 安全程序集，不增加依赖或改变凭据格式。此前 0.3.1 的 30 秒等待上限未能解决该问题；该有限上限继续保留。0.3.0 后的 CI 修正还为真实双书库与 DPAPI 集成测试分配了独立时限，所有功能断言保持不变。

## 变化

- 在统一设置中新增“同步”：Google 桌面客户端导入、系统浏览器授权、加密书库创建／加入、恢复密钥、范围开关、暂停和重试。
- 同步引擎按实体记录父版本，保留离线分叉；版本和附件加密，上传可恢复且可幂等重试。同步不改变本地优先的保存行为。
- 笔记、文件夹、批注、引用、Note Bots、书签与各设备阅读位置参与同步；原书和图片按需下载，外观与快捷键可选。
- 保留远端删除时的打开草稿并提供恢复入口；凭据和运行中的 AI 对话不参与同步。
- 包含 0.2.19 的 EPUB 卸载、重排定位及书源保存完成时序修复；该修复提交的远程 CI 已通过。

## 验证与限制

测试使用项目原创 TXT／EPUB／PDF、隔离的两个 Reader 数据目录、模拟 Drive 及模拟 OAuth 响应。Windows 安全存储测试调用实际 DPAPI；UI 使用构建后的生产页面和隔离 API。具体执行结果以交付日志与 CI 为准。

2026-10-30 本地通过 `npm run check`（369 项单元／集成测试、5 项平台测试、类型检查、构建与插件校验）及完整 Playwright 回归（122 项）。其中真实 Google 网络与实际宿主页面均不属于这些隔离测试的证明范围。

2026-10-31 完成真实 Google 账户、两份隔离 Windows 书库的联调：加密云端读写、恢复密钥加入、按需下载、图片、书签、设备位置与冲突保留通过，8 个原创测试云对象均已清理。未上传个人书库，也未把同机隔离测试表述为不同物理电脑的实机验证。代码提交的[完整 CI](https://github.com/Quiyyy/reader-plugin/actions/runs/41098617436)已通过；其中 Windows runner 的一次网络缓冲区错误通过单独重跑该任务完成验证。

首次连接需要用户的桌面 OAuth 配置及浏览器授权。当前不支持多人实时编辑、关闭 Reader 后的常驻同步、历史垃圾回收、AI 对话同步或在线书源配置复制。删除条目不代表抹除全部历史副本。

配置、边界和恢复步骤见 [Google Drive 同步指南](GOOGLE_DRIVE_SYNC.md)。
