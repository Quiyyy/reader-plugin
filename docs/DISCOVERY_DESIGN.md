# Reader 找书与书源体验改版

## 审查基线与验证边界

审查基于已安装 Windows Reader 0.1.5，源提交 `e7f6f65e736d7daca61c6b80c613ba265af62f3c`。只读核对安装包 `runtime-manifest.json` 和原始 UI 的 SHA-256：`ecf7b54172e506e70d626b4167559451c4851a3545f7f9ac47abb59f430059d1`。

先查看升级任务保存的安装资源预览截图和当前源码，再以安装包的原始 HTML、独立临时测试服务及原创 fixture 复现旧界面。`artifacts/baseline-installed-ui-{320,390,1280}.png` 是浏览器预览；不是 ChatGPT 原生宿主截图。未自动化 ChatGPT UI，未修改正式安装、书库、配置、安全策略或凭据。正式宿主的原生面板布局与导航仍需主任务人工核验。

## 当前形态的五个问题

1. 「在线书源」弹窗同时承载导入、管理、诊断、搜索、详情，搜索被排到管理内容之后。
2. 明明已有启用来源，用户仍需先选来源；书架本地筛选与在线搜书的入口也不够清楚。
3. `supported`、`passed` 和分阶段表格出现在核心流程，用户需要先理解内部规则才能行动。
4. 导入预览强调字段差异，保存和实际可读没有足够直观的区分，保存后缺少连贯的下一步。
5. 进入正文卸载弹窗，返回后关键词、筛选、结果、详情均丢失，必须重新开始搜索。

## 信息架构与行为

- 一级：书架 / 找书。书架保留继续阅读、本地导入和本地筛选，紧凑正文工具栏不增高。
- 次级：找书页右上角进入书源管理。启停状态与可用性摘要分别显示；技术诊断折叠，移除需在当前条目中确认。
- 导入：文件或 URL → 摘要与新增/更新说明 → 确认保存 → 启用并找书。关闭/重新选择不提交；提交期间禁用重复操作，网络检查可取消，迟到响应不会重开向导。
- 找书：默认全部启用来源，可筛选单源。最多 3 个请求并发，每个请求沿用原网络策略。正常结果先显示，来源故障折叠在下方，重试故障来源保留成功结果。
- 详情：来源、作者、简介与「开始阅读」。自动入架，返回时保留会话内搜索状态。取消、空结果、末页、错误重试均有明确反馈。
- 无书源/无启用源分别给「导入书源」「去启用书源」；也能直接返回书架阅读本地文件。

未改动服务器规则、安全策略、工具协议、书库结构、章节稳定 ID 或缓存保存。没有加入推荐、脚本执行、登录或自动获取来源。保持 Reader 名称及既有紧凑标题设计；导航占用的空间通过收起书架装饰文案和压缩间距抵消，原有书架首排高度回归标准保持不变。

## 验证与证据

`npm run check` 覆盖静态检查、111 个单元/集成测试、构建、插件检查和 5 个平台测试。浏览器测试使用真实 Reader 服务、真实规则解析和存储、原创文本 fixture；仅 fixture 的受控 HTTP 连接例外属于测试构造器。

`tests/e2e/discovery.spec.ts` 新增向导键盘焦点循环与恢复、关闭不保存、同步重复点击只提交一次、保存后不自动启用、启用并找书、错误恢复、取消/直接关闭后的迟到响应、失败来源与可读结果共存、只重试失败来源，以及阅读后恢复详情、关键词和结果焦点。网络时序测试仅延迟真实 fixture 返回，用于验证界面竞态。

`tests/e2e/online.spec.ts` 和 `online-imports.spec.ts` 继续覆盖文件/URL 的单源和数组、搜索空结果/末页、四步联网状态、脚本拦截、内容纯文本、目录/正文分页、书签进度、子进程重启和断网缓存。原 TXT/EPUB、文件入口与 MCP Apps 协议测试保留。

截图由 CI 作为 browser-evidence 上传，也保存在本地 `artifacts/`：

- `redesign-empty-{320,390,1280}.png`：无书源的直接下一步。

原设计审查分支 `feature/legado-reader-discovery-design` 使用仓库现有的免发布前缀；`c6e72c6` 的审查 CI 不触发市场预览或正式发布。用户随后批准发布和升级，0.1.6 发行分支保留这版设计，递增包版本及 UI 资源地址，并重新经过候选、main 和六平台市场安装的完整门槛。正式升级前需重新备份最新书库、来源及缓存；macOS 自包含包的 `NOT_AVAILABLE` 信任限制保持不变。
