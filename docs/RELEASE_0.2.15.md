# 0.2.15 快速笔记与 Note Bots

## 编辑与对话

- 保留一级入口，命名为“快速笔记”。书库与快速笔记访问同一份笔记数据。
- 默认直接编辑排版后的正文，顶栏可切换 Markdown 源码。格式工具栏默认关闭，开关位于笔记操作菜单。
- 参考 Space 选区工具条与原生输入框的视觉布局：文档正文居中，选中文字时显示胶囊工具条，底部始终保留对话框。
- 编辑模式通过代码／铅笔图标切换，Bot 使用点阵标志。宽窄屏共用相同的输入框与图标操作，选区上下文放在输入框内。
- 选区支持提出修改要求、加粗、斜体、下划线、删除线、行内代码、段落样式与评论。正文块支持拖动整理。
- 底部对话可连续追问、选择模型、附图、停止回复、展开或收起历史；草稿随当前笔记的会话保存。

## Note Bots

可创建多个 Bot，配置名称、用途、职责指令与默认模型，并选定默认 Bot。正文或输入框中的 `@` 打开选择器，支持鼠标和方向键／Enter。选中 Bot 不会自动发送。

Bot 通过已有官方 Codex CLI 连接工作；无需新增模型凭据。自定义指令不扩大工具权限。底部建议会话仅提供当前笔记与已关联资料的读取工具，不能直接调用写入工具。

## 数据保护

- 笔记仍以 Markdown 保存；切换模式本身不重写正文。HTML、脚注定义等不直接支持的块保留为字面源码。
- AI 结果由用户选择替换或插入，可撤销。采用前同时核对原选区对应的正文与笔记版本，避免覆盖生成期间的新输入或其他窗口的修改。
- Bot 配置独立存放于 `study-v1/note-bots.json`，使用版本校验与原子写入。删除默认 Bot 后切换到剩余 Bot，至少保留一个助手。
- 评论随笔记保存并参与 Markdown 导出。图片、引用与既有笔记草稿保护继续沿用原流程。
- 修复 Windows 偶发文件占用导致的原子保存失败，进行有界重试；持续失败时保留原文件并报告错误。

## 实现与验证范围

所见即所得基于 Tiptap，生产 UI 仍为自包含资源，不加载外部编辑器脚本。编辑、评论、Bot、选区采用、并发保护与恢复流程使用隔离书库验证；AI 回复界面场景使用受控响应，传输与权限由独立协议测试覆盖，不将其称为真实模型或桌面宿主验收。

交付遵循 [本地更新方案](LOCAL_UPDATES.md)，不自动安排额外的宿主页面复核。

设计与技术参考：[Typora Live Preview](https://support.typora.io/Quick-Start/#live-preview)、[Notion Custom Agents](https://www.notion.com/help/custom-agents)、[Tiptap Markdown](https://tiptap.dev/docs/editor/markdown/getting-started/basic-usage)。Space 视觉依据为本次需求中提供的工具条与输入框截图。
