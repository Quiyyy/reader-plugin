# Reader 0.1.10

打开在线书籍时，目录第一页解析完成即保存书籍并读取首章。尚未完整的目录明确显示“目录未完”，已知章节可立即选择；到达已知目录尾部显示“加载更多章节”，不再误称“本书完”。下一页续点、规则变量和累计资源计数随书籍持久保存，临时分页草稿被清理或服务重启后仍能接续。

阅读界面保留当前、前一章和后一章正文，最多三章、12 MiB 邻章内存预算。空闲 900 ms 后只预取下一章，复用源限速、取消和请求合并机制；前台点击相同目标接续该请求。缓存切回不需要宿主 RPC。切章立即展示，进度仍通过原有串行保存队列提交；返回书架和关闭前继续等待保存，失败可重试。

已有完整目录的刷新维持完整后替换，更新时按稳定章节 ID 保留书签与位置。多页正文仍在整章完成后展示，失败、取消不会用部分正文覆盖缓存。本版未改网络连接池、DNS 固定、安全边界或 Worker 架构。

## 针对验证

- 类型检查和生产构建通过；服务相关 78 项用例通过。
- 本机三个界面用例通过：增量目录、长章继续、缓存切回与慢进度保存。
- 原创慢目录：15 页，每页响应人为延迟 120 ms；首章可读只请求第一页目录和第一章，共 2 次请求，单次测得 340 ms。此数字不代表真实网站网络耗时。
- 故意阻塞进度保存时，内存缓存切回单次测得 40 ms，未增加章节 RPC；空闲预取仅一次下一章请求。
- 40 页 / 8000 章原创目录验证累计预算、重启续点与不下载全书正文；失败/取消保留记录、缓存、进度及书签。

本次按照维护者授权手动发布，不等待远端 CI，不执行跨平台反复验收。Mac 使用既有 Node 安装方式，并保留旧版和完整数据备份。Windows/Linux 包为同一源码构建；本次未执行这些平台的本机运行验证，未升级离线 Windows 设备。
