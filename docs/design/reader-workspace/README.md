# Reader 产品交互实验室

产品设计见 [PRODUCT_DESIGN.md](PRODUCT_DESIGN.md)。本目录是独立的设计原型，不进入 Reader 发行包。原型没有远程请求，也不连接正式书库。示例正文、封面、PDF 图表和笔记均为本项目原创。

## 启动与阅读

在仓库根目录运行：

```powershell
node tools/ui-lab/serve.mjs --root docs/design/reader-workspace --port 4186
```

打开 http://127.0.0.1:4186/design.html 阅读图文设计稿；打开 http://127.0.0.1:4186/lab.html 使用交互实验室。结束后按 Ctrl+C 停止。可以使用 `--port 0` 让系统分配端口。静态服务只监听 loopback，只读取指定目录，拒绝越界路径和不支持的方法，没有控制或数据写入接口。

宽屏、900px、390px 与 320px 可切换。状态包括空内容、离线、保存失败、来源缺失与连接不可用；切换场景不重置已经保存的原型笔记。点击“重置”只清理当前原型自己的示例数据、对话和外观。原型内容保存在浏览器的 `reader-product-design-v1` 及其派生键中；这不是生产持久化方案。

## 可体验的流程

1. 点击实验室顶部“选区示例”，或手动在 EPUB 中划选文字。工具条使用图标，悬停或键盘聚焦显示名称。
2. 高亮、填写批注，或选择“问 Codex”。后一操作打开 Reader 浮窗，来源折叠为短标签。
3. 输入问题并发送，可连续追问；浮窗明确标注演示，回答不来自真实模型。可以拖动、收起、关闭后重开、切换话题，并把回答保存为有来源的笔记。
4. 编辑笔记，点击来源卡回到原文，再返回笔记。
5. 切换 PDF 场景，点击“框选区域”，拖动并查看实际区域截图；可提问或加入笔记。
6. 新建文件夹、移动书籍或笔记、搜索、放入回收站并恢复。
7. 在保存失败场景编辑文字，观察持续状态和重试；在来源缺失场景尝试恢复引用。
8. 从外观图标配置模式、预设或自定义强调色与纸色。修改即时预览，完成后保存，取消恢复旧值；刷新保留已保存外观。

## 已模拟与待实现的边界

| 范围 | 原型中的行为 |
| --- | --- |
| 阅读、划选、笔记编辑、批注 | 对原创数据执行本地交互；原型数据可重置 |
| PDF | Canvas 绘制的原创页面示意，支持对实际画布区域裁剪；没有 PDF 解析器 |
| Codex 对话 | Reader 内容上方的可拖动浮窗，支持话题、草稿与多轮演示；回答固定，不调用模型。“交给原生对话”仅提供交接预览与复制 |
| 外观 | 用户可配置强调色、明暗与纸色，支持预览、取消、恢复默认和本浏览器持久化 |
| Space | 只预览整理请求；不会创建 Page、上传内容或假装返回成功链接 |
| 导入 | 展示导入与重复处理流程，仅使用内置示例，不读取个人文件 |
| 格式编辑 | 以可编辑纯文本和基础 Markdown 标记表达；不代表最终富文本编辑器选型 |
| 引用 | 演示从来源卡回到段落与笔记；真实跨版本恢复与位置稳定性属于后续产品实现 |
| 并发修改、批量操作、OCR | 产品文档定义体验；本原型未实现这些能力 |

## 与现有调试系统的分工

本仓库已有 `npm run inspect:reader`，使用生产构建、真实原生 MCP 服务及模拟 AppBridge，专门检查协议和生产 UI。此次原始界面基线使用隔离书库和原创 EPUB，报告位于 `artifacts/design-baseline/report.json`。

本实验室专门用于讨论未来界面、宽度与异常状态。`tools/ui-lab/serve.mjs` 的静态根目录可以换成另一个插件原型；场景控制位于 `lab.js`，阅读浮窗和外观位于 `study-interactions.js`。它不是通用 MCP 宿主实现，也不宣称覆盖所有插件。

两套工具都不能证明真实 Codex 的入口、文件资源、消息发送或原生面板行为已通过验收。真实宿主未提供可用控制接口时，不使用私有管道、远程调试接口或放宽生产 CSP 来替代。

## 复现界面验证

安装仓库锁定的开发依赖后，运行：

```powershell
npm run inspect:reader -- --surface bridge --scenario epub --output artifacts/design-baseline
node tools/ui-lab/check-reader-design.mjs
```

验证使用本机 Edge 或 `CHROMIUM_PATH` 指定的 Chromium，不下载浏览器。截图写入本目录的 `assets`；交互结果、错误和溢出检查写入 `artifacts/reader-design-checks/report.json`。生产界面基线和产品原型分别记录。

第一条命令生成当前生产 UI 的隔离基线，第二条校验交互原型并更新 `design.html` 的静态阅读版。日常启动服务器无需重新运行验证，也不需要生产构建。`PRODUCT_DESIGN.md` 是正文编辑源；服务器提供的 `/design.html` 每次读取最新 Markdown。

本轮检查结果见 [VERIFICATION.md](VERIFICATION.md)。
