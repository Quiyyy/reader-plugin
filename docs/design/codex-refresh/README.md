# Reader · Codex 风格设计提案

本轮提供三套独立的首页书库与阅读聊天小窗设计。产物是可交互 HTML 和浏览器实际渲染的 PNG，不修改生产界面、服务端或正式书库。

| 方案 | 首页书库 | 聊天小窗 | 适用偏好 |
| --- | --- | --- | --- |
| A · 原生简洁 | 收紧导航、继续阅读横条、紧凑列表、并列最近笔记 | 中性浅色、灰色用户气泡、黑色发送按钮、就近引用 | 优先与 Codex 协调，建议作为默认方向 |
| B · 轻盈书房 | 顶部导航、最近阅读双卡、封面网格 | 纸感底色、左对齐提问、柔和绿色操作、来源标签 | 更看重书籍识别与阅读氛围 |
| C · 专注工作台 | 图标导航、按阅读状态分组、最近笔记侧栏 | 深色浮窗、话题条、深色引用标签、高对比输入区 | 藏书较多、重视阅读与笔记并行 |

已选择 C 的工作台布局作为生产实现方向。布局与配色分离，同一套组件支持浅色、深色、跟随系统、暖纸和自定义强调色。原始三版提案保留供对照。

## C 方案实现

打开 [实际界面预览](http://127.0.0.1:4188/implementation.html) 对比同一布局的浅色、深色、暖纸与窄屏截图。图片来自生产构建与隔离测试书库；聊天消息为浏览器测试夹具，没有为截图调用真实模型。

- `src/ui/LibraryShelf.tsx`：紧凑的继续阅读入口、正在阅读／稍后阅读／已读完分组、卡片／列表切换、右侧最近笔记。窄屏把笔记放到列表下方。
- `src/ui/ReadingChat.tsx`：简洁标题栏、独立话题条、可回跳的消息引用、附带来源的圆角输入区、原生对话交接入口。保留会话、草稿、拖动、收起和权限行为。
- `src/ui/workspace-layout.css`：只负责布局、间距、尺寸与控件形状，不按主题切换布局、不包含颜色常量。
- `src/ui/appearance.ts`：统一语义颜色。跟随系统时优先使用宿主明确提供的明暗模式，再回退到系统设置。
- 新书库默认列表视图，已保存的卡片／列表偏好继续保留；更改明暗、纸色或强调色不会修改布局设置。
- 在线目录尚未完整时，读到当前目录末尾不标记为全书已读完。

验证包括 31 项浏览器检查、19 项相关单元检查、TypeScript 和脚本语法检查。已检查浅色与深色几何尺寸完全一致、暖纸与强调色保存、320／390px 下主要控件可见、分组切换、搜索、原文回跳、草稿恢复和拖动后缩窄窗口。

生产 EPUB 基线位于 `artifacts/workbench-bridge-inspection/report.json`，检查通过。它使用模拟 AppBridge 和原生 MCP，不等于真实 Codex 宿主安装验收。

## 设计依据

- 用户提供的当前书库截图：大面积蓝色、重复搜索入口、继续阅读与书籍卡片偏大。
- 当前 `src/ui/ReadingChat.tsx`、`src/ui/workspace.css` 和既有交互实验室，确认会话、引用、收起、交给原生对话等现有行为。
- 本地安装的 `@openai/apps-sdk-ui` 语义变量：中性灰、主次文字、4px 间距阶梯、8/12/16px 圆角。这里只借鉴视觉语言，不声称精确复刻当前 Codex 宿主的私有设计规范。
- 本轮生产基线：`artifacts/codex-refresh-baseline/report.json`，使用隔离数据与原创 EPUB，检查通过。这是模拟 AppBridge 配合原生 MCP 的检查，不是真实 Codex 宿主验收。

界面与书籍封面均用 HTML/CSS 构建；示例书籍、书籍正文和回答均为设计演示数据。颜色不是唯一的状态表达，图标操作保留可访问名称与键盘焦点。

## 复现与验证

```powershell
node docs/design/codex-refresh/render.mjs
```

使用现有 Playwright 与本机 Edge（或 `CHROMIUM_PATH`），临时启动已有静态服务器，结束后自动关闭。生成 15 张截图与 `verification.json`。检查三个方案在 1280、390、320px 下的水平溢出、脚本错误、外部请求，以及搜索、筛选、来源展开与移除、演示追问、聊天收起恢复和方案切换。

预览通过上述检查并进行截图目视复核；这不代表聊天后端、真实导入、拖动、持久化或真实宿主集成已经实现或验收。
