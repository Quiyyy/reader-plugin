# Reader local delivery

- Follow `docs/WINDOWS_DELIVERY.md` for authorized local plugin updates.
- For a running desktop host, use `prepare → stage → desktop Reader Install/Update → complete`. The desktop installation action rebuilds the original chat's MCP bindings. Do not use external `codex plugin add` as a substitute for that action.
- Keep the currently installed package running while preparing and staging a different version. Same-version repair that requires closing Reader processes or uninstalling the plugin needs explicit user authorization unless already granted in the session; never close unrelated processes.
- After every accepted local delivery, automatically schedule the single follow-up heartbeat generated by `scripts/reader-host-sync.mjs`. The user chose delivery-triggered synchronization, not periodic polling.
- Installation and host activation are separate gates. Do not call the upgrade fully synchronized until the actual MCP App's `reader-version` metadata matches the delivered version and its screenshot is recorded.
- Schedule the follow-up as the final delivery step. It only rechecks the result; starting another turn or a heartbeat does not itself replace the original chat's MCP connection. Do not ask the user to manually update or send “continue” to activate each version.
- Use supported host tools. If host reconnection or actual UI verification is unavailable, leave synchronization pending and state the limitation; do not terminate the desktop app or fabricate success from a separate server process.
