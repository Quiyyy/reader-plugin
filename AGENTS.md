# Reader local delivery

- Follow `docs/WINDOWS_DELIVERY.md` for authorized local plugin updates.
- After every accepted local delivery, automatically schedule the single follow-up heartbeat generated by `scripts/reader-host-sync.mjs`. The user chose delivery-triggered synchronization, not periodic polling.
- Installation and host activation are separate gates. Do not call the upgrade fully synchronized until the actual MCP App's `reader-version` metadata matches the delivered version and its screenshot is recorded.
- Schedule the follow-up as the final delivery step and finish the current turn, so the follow-up runs with a newly loaded session context. Do not ask the user to manually update or send “continue” to activate each version.
- Use supported host tools. If host reconnection or actual UI verification is unavailable, leave synchronization pending and state the limitation; do not terminate the desktop app or fabricate success from a separate server process.
